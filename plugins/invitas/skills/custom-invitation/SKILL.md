## Español

1. Identifica el evento con `list_events` y `get_event`. Consulta `guide` con `topics: ["html_propio"]` y `list_html_designs` para ver disponibilidad, requisitos, diseño activo y versiones. HTML propio está disponible desde Animado, incluso en el dominio propio verificado del evento. Si faltan las herramientas o `availability.available` es falso, explica el motivo conocido y detén el flujo.
2. Si el usuario parte de un PDF, pídele que adjunte el archivo al chat. Usa la lectura de archivos del cliente para tomar como referencia la composición, los colores y los recursos visuales. Si el cliente no puede leerlo, pide imágenes de las páginas. Confirma los datos que discrepen del evento. Rehaz el diseño como una página adaptable con texto seleccionable y los datos actuales de `window.INVITAS`. El PDF queda como referencia en el chat y `submit_html_design` recibe el HTML. Si necesitas imágenes, sigue la guía para añadirlas por separado al evento.
3. Crea un documento HTML completo con CSS y JavaScript en línea. El marco funciona sin peticiones de red del diseño, librerías externas, iframes ni formularios propios. Usa los recursos que entrega invitas. Apunta a 60 KB y mantén cada envío por debajo de 200 KB para dejar margen al conector. El documento guardado tiene un máximo de 512 KB.
4. Integra un botón visible y operable con `data-invitas-action="rsvp.open"` dentro de una única ranura `<invitas-slot name="rsvp">` en el cuerpo. Si el evento tiene música, integra un botón visible y habilitado con `data-invitas-action="music.toggle"` y actualízalo con `invitas:music-state`. Invitas abre el formulario de confirmación y reproduce la música tras un toque. Para video de portada, usa `INVITAS.media.heroVideo` cuando esté disponible. Conserva sus URL tal como llegan y usa un video silenciado con `playsinline`, póster y control de reproducción. Respeta las preferencias de movimiento y ahorro de datos. Muestra la foto cuando no haya video.
5. Guarda con `submit_html_design`. Corrige los errores del informe y vuelve a enviar. Si queda en `checking`, espera y consulta `list_html_designs`. Para `ready`, `awaiting_review` o `approved`, usa `preview_html_design` con `eventId`, `designId` y `version`. Comparte el enlace temporal solo con el anfitrión y comprueba las capturas de móvil y escritorio si están disponibles.
6. Pide el visto bueno del anfitrión para esa versión antes de llamar a `activate_html_design`. Si devuelve `awaiting_review`, informa que la versión está pendiente y vuelve a consultar su estado con `list_html_designs`. Publicar un evento en borrador requiere confirmación aparte. Para restaurar la invitación clásica, confirma el cambio y usa `update_event` con `config.layout: "classic"`.

## English

1. Identify the event with `list_events` and `get_event`. Call `guide` with `topics: ["html_propio"]` and `list_html_designs` for availability, requirements, the active design and saved versions. Custom HTML starts with Animado and works on the event's verified custom domain. If the tools are missing or `availability.available` is false, explain the reason if known and stop the design workflow.
2. For a PDF, ask the user to attach the file in chat. Use the client's file reader to reference the composition, colors and visual assets. If the file cannot be read, ask for images of the pages. Confirm details that conflict with the event. Rebuild it as a responsive page with selectable text and live values from `window.INVITAS`. Keep the PDF as a chat reference and pass the generated HTML to `submit_html_design`. Follow the guide to add any needed images to the event separately.
3. Build a complete HTML document with inline CSS and JavaScript. The frame runs without network requests from the design, external libraries, iframes or custom forms. Use the assets supplied by invitas. Aim for 60 KB and keep each submission under 200 KB to leave room for the connector envelope. The stored document limit is 512 KB.
4. Place a visible, usable button with `data-invitas-action="rsvp.open"` inside exactly one `<invitas-slot name="rsvp">` in the body. If the event has a song, add a visible, enabled button with `data-invitas-action="music.toggle"` and update it on `invitas:music-state`. Invitas opens the RSVP form and plays the song after a tap. For cover video, use `INVITAS.media.heroVideo` when available. Keep its URLs as supplied and use muted video with `playsinline`, a poster and a playback control. Respect reduced motion and data-saving preferences. Show the cover photo when video is unavailable.
5. Save with `submit_html_design`. Fix the reported errors and resubmit. For `checking`, wait and call `list_html_designs` again. For `ready`, `awaiting_review` or `approved`, call `preview_html_design` with `eventId`, `designId` and `version`. Share the temporary link only with the host and check the mobile and desktop screenshots when available.
6. Ask the host to approve that version before calling `activate_html_design`. If the result is `awaiting_review`, report that the version is pending and check its status with `list_html_designs`. Publishing a draft event requires separate confirmation. To restore the classic invitation, confirm the change and use `update_event` with `config.layout: "classic"`.

## Português

Consulte `guide` com `topics: ["html_propio"]` e `list_html_designs` para verificar disponibilidade, requisitos, design ativo e versões salvas. O HTML próprio está disponível a partir do Animado, inclusive no domínio próprio verificado do evento. Se as ferramentas estiverem ausentes ou `availability.available` for falso, explique o motivo conhecido e encerre o fluxo de design.
2. Se a pessoa partir de um PDF, peça que anexe o arquivo à conversa. Use a leitura de arquivos do cliente para tomar a composição, as cores e os elementos visuais como referência. Se não conseguir ler o PDF, peça imagens das páginas. Confirme os dados que divergirem do evento. Recrie o design como uma página adaptável com texto selecionável e dados atuais de `window.INVITAS`. O PDF fica como referência na conversa e `submit_html_design` recebe o HTML. Siga o guia para incluir as imagens necessárias separadamente no evento.
3. Crie um documento HTML completo com CSS e JavaScript embutidos. O quadro funciona sem requisições de rede feitas pelo design, bibliotecas externas, iframes ou formulários próprios. Use os recursos fornecidos pelo invitas. Procure ficar perto de 60 KB e mantenha cada envio abaixo de 200 KB para deixar margem no conector. O documento salvo tem limite de 512 KB.
4. Inclua um botão visível e utilizável com `data-invitas-action="rsvp.open"` dentro de um único `<invitas-slot name="rsvp">` no corpo. Se houver música no evento, inclua um botão visível e habilitado com `data-invitas-action="music.toggle"` e atualize-o com `invitas:music-state`. O invitas abre o formulário de confirmação e toca a música após um toque. Para o vídeo de capa, use `INVITAS.media.heroVideo` quando disponível. Preserve as URLs recebidas e use vídeo sem som, com `playsinline`, pôster e controle de reprodução. Respeite as preferências de movimento reduzido e economia de dados. Mostre a foto de capa quando o vídeo estiver indisponível.
5. Salve com `submit_html_design`. Corrija os erros do relatório e reenvie. Se estiver em `checking`, aguarde e consulte `list_html_designs` novamente. Para `ready`, `awaiting_review` ou `approved`, use `preview_html_design` com `eventId`, `designId` e `version`. Compartilhe o link temporário apenas com a pessoa anfitriã e confira as capturas de celular e computador quando disponíveis.
6. Peça a aprovação da pessoa anfitriã para essa versão antes de chamar `activate_html_design`. Se retornar `awaiting_review`, informe que a versão está em análise e consulte seu estado com `list_html_designs`. Publicar um evento em rascunho exige confirmação separada. Para restaurar o convite clássico, confirme a mudança e use `update_event` com `config.layout: "classic"`.
